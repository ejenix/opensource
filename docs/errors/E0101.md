# E0101 — Unsupported top-level declaration

The source is valid Dart, but it declares something at the top level that the
Ejenix compiler does not lower.

## Why

A compilation unit is lowered declaration by declaration, and almost every
top-level form is now supported: functions, classes, `enum`, `mixin`,
`extension`, `extension type`, `typedef`, and every constructor form. This
error has therefore become narrow — it fires on the one remaining gap:

- **Top-level variables.** A bare `int counter = 0;` would be mutable module
  state living outside any capability the host can reason about, so it is
  rejected rather than silently given semantics nobody agreed on.

If you hit E0101 on anything other than a top-level variable, that is a bug —
please file it.

## Example

```dart
int counter = 0;

int main() => counter;
```

```
input.dart:1:1: error [E0101]: top-level `TopLevelVariableDeclaration` is not yet supported
```

## How to fix

- Use a **`static` field** on a class. It lowers to a module global and does
  everything a top-level variable would:

  ```dart
  class Counters {
    static int value = 0;
  }

  int main() => Counters.value;
  ```

- If the value belongs to the app rather than the patch, expose it as a **host
  capability** and let the shipped binary own it (see `spec/host-api.md` and
  `example/patchable_app/`). State the app owns is state a patch cannot
  corrupt.

- See `spec/dart-subset.md` §3 for the current list of gaps.
