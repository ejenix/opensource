# E0200 — Sandbox-forbidden import

The source imports a Dart core library that is **permanently forbidden** inside
the Ejenix interpreter sandbox. Unlike an unsupported-subset error, this is not
a gap that will be filled later: allowing these libraries would defeat the
security boundary that makes Ejenix over-the-air patching safe.

## Why

Interpreted bytecode is code you ship *after* the app is on a user's device. The
sandbox's whole guarantee is that such code can reach the host platform **only**
through the explicit allow-list (`HostRegistry`, see `spec/host-api.md`). These
libraries would each punch a hole straight through that boundary:

| Import | What it grants | Why it is forbidden |
| --- | --- | --- |
| `dart:ffi` | Calls into native code and raw memory | Runs arbitrary machine code — a total sandbox escape |
| `dart:io` | Files, sockets, processes | The host registers no such capability, so it could only fail on a device |
| `dart:mirrors` | Runtime reflection | Bypasses the host allow-list and defeats static reasoning |
| `dart:isolate` | Spawns uncontrolled isolates | Escapes the interpreter's supervised loop and resource limits |

Raw platform channels are excluded by the same principle: native capability must
be surfaced as a named host capability, never reached directly (brief §6.2,
§6.10).

## Example

```dart
import 'dart:ffi';

void f() {}
```

```
input.dart:1:1: error [E0200]: `dart:ffi` is not permitted in the sandbox
  (native code and raw memory access)
  correction: expose only the specific capability you need through the host
  API (HostRegistry), rather than importing this library
```

## How to fix

- Identify the single concrete capability you actually need (e.g. "take a
  photo", "read this file") and expose **that** from the host app as an
  allow-listed host function. The interpreted patch calls the capability; it
  never touches the native library directly.
- Register the capability in the host's `HostRegistry` — see `spec/host-api.md`
  for the binding convention.
- This error will not be removed by a future release; the exclusion is by
  design. See `spec/dart-subset.md` §3.
