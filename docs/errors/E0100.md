# E0100 — Unsupported expression or statement

The source is valid Dart, but it uses an expression or statement outside the
Ejenix compiler's supported subset. Rather than mis-compile it, Ejenix rejects
it with this code and, where possible, a suggested alternative.

## Why

The compiler targets a growing subset of Dart. Everything in the subset
compiles, runs, and is tested; everything else is reported here, so intent is
never silently mis-lowered.

## What the message looks like

The diagnostic names the exact construct it could not lower, at its exact
location:

```
input.dart:12:18: error [E0100]: expression `SomeExpression` is not yet supported
```

The construct name comes from the analyzer's AST, so it is the precise node the
compiler stopped on rather than an approximation.

## Which constructs trigger it

**[`spec/dart-subset.md`](../../spec/dart-subset.md) is the authoritative
list.** Check there, not here.

This page used to enumerate unsupported constructs inline and the list rotted
badly: it named `try`/`catch`, cascades, records, patterns and `await` as
outside the subset long after all of them were supported, and its worked example
was a `switch` expression that compiles today. A developer scoping what a patch
could do would have under-used the product and distrusted the rest of the docs.

The subset is wide — classes, generics, mixins, enums with members, closures
capturing `this`, operators, cascades, records, patterns, spreads, labelled
breaks, `async`/`await`, and both generator forms all compile. If you hit this
error, the message names the construct; the spec says whether an alternative
exists.

## How to fix

- Read the construct name in the message and find it in
  [`spec/dart-subset.md`](../../spec/dart-subset.md).
- Follow the `correction` hint when the diagnostic offers one.
- Rewrite using a supported form — most rejections have a direct equivalent.
- If the feature is essential to your patch, open an issue; the subset expands
  milestone by milestone.
