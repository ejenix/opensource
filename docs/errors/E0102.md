# E0102 — Too many registers

The Ejenix compiler needs more registers for one function than the bytecode
format can encode. A register index is a single byte, so a function may use at
most **255**.

## Why

Ejenix bytecode is register-based: every parameter, local, and intermediate
value lives in a numbered slot, and the operand naming a slot is 8 bits wide. A
function with more simultaneously live values than that cannot be expressed.

This used to be clamped silently, which was worse than an error. The function
compiled, was signed, and shipped — but its registers aliased one another, so it
computed wrong answers on a real device with nothing to point at. The encoder's
own range checks were `assert`s, which are stripped from release builds, so
nothing caught it downstream either. The compiler now refuses the build.

## How to fix it

Reduce the number of values live at once in the reported function.

- **Split it.** Extracting part of the body into a second function is usually
  the smallest change — each function gets its own register file.
- **Shorten lifetimes.** A local computed at the top and used only at the bottom
  occupies a slot for the whole body. Move the computation next to its use.
- **Collapse long expression chains.** Deeply nested expressions hold many
  intermediates simultaneously.

A very large `build()` assembled from a design system is the usual cause;
splitting the widget tree into sub-widgets fixes it and reads better anyway.
